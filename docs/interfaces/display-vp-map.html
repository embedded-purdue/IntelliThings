Companion display VP map

Version 1.0. What the node firmware writes to show real data on the IntelliThings display. Every value is a 16-bit word at a VP address, written with an ordinary DGUS II write frame, as the firmware architecture plans for the DWIN display. The display turns the values into the screens and the light bar; anything you don't write keeps its power-up value.

Write frame

5A A5 <len> 82 <VP hi> <VP lo> <data…>

  • len = 3 + data bytes. Data is whole 16-bit words, high byte first: at most 240 bytes (120 words) per frame. One frame may cover several variables in a row.
  • The display answers 5A A5 03 82 4F 4B ("OK"). No CRC.
  • Read back: 5A A5 04 83 <VP> <n> → 5A A5 <4+2n> 83 <VP> <n> <words>.

Values

  • Readings: 0x8000 = no reading. Temperature and humidity are × 10 (224 = 22.4 °C); temperature is signed.
  • u32: two words, high word first.
  • Text: UTF-8, two bytes per word (first byte in the high half), ending with a 0x00 byte. A first word of 0x0000 = empty.
  • Characters drawn: A–Z a–z 0–9 ! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ \ ] ^ _ ` { | } ~ ° ₂ µ ³ · … ’ ‘ “ ” – — − ×. Others are skipped.

Where to send it

  • Bench, now: a UART to the companion ESP32-C6 that drives the panel, 115200 8N1, 3.3 V: node TX → companion GP2, companion GP3 → node RX (for the "OK" replies), and GND to GND. Or from a laptop over the companion's USB with tools/companion.py.
  • One-chip node, later: the same VPs, in-process: companion_ui::vp::Inputs::write(vp, words, now).

The minimum for a working demo

  • Sensor readings every 0.5–1 s
  • wifi, hub, synced_ago when they change
  • The clock once after SNTP
  • message_text (and message_ts) for each MQTT …/display message. The AI section shows about 110 characters (80 with action chips).
